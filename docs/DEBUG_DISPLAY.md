# Debug Display Specification

This document defines the architecture, display format, and variable-driven evaluation rules for the RadarMap tactical debug overlay.

---

## 1. Overview & HUD Placement

The debug display provides live, zero-overhead diagnostic telemetry directly on the tactical radar map HUD.

- **Placement**: Upper-right corner of the HUD (mirrors the session status button on the left).
- **Visibility Control**: Gated by `@AppStorage(AppConstants.Storage.isDebugDisplayEnabledKey)`.
  - Default: **Disabled** (`false`).
  - Runtime Toggle: Accessed via the hidden **Debug Panel** ([`DebugUnlockView.swift`](../RadarMap/Views/Settings/DebugUnlockView.swift)), reached by holding the Policy screen for 5 seconds and entering the administrative passcode.
- **Rendering Elements** (defined in [`TacticalRadarMapView.swift`](../RadarMap/Views/Map/TacticalRadarMapView.swift)):
  1. **Line 1**: Build Version String (`AppConstants.Version.formattedVersionString`).
  2. **Line 2**: 8-Character Netcode Status String (`GameStateManager.debugStatusString`).

---

## 2. Line 1: Build Version String

Formatted via [`AppConstants.Version.formattedVersionString`](../RadarMap/AppConstants.swift) and generated into [`AppBuildVersion.swift`](../RadarMap/Models/AppBuildVersion.swift):

```
v{marketingVersion}b{buildNumber}
```

- **Example**: `v1.0.0b530`
- **Typography**:
  - iOS: Monospaced 9pt bold, themed color with 0.6 opacity.
  - watchOS: Monospaced 6pt bold, themed color with 0.55 opacity.

---

## 3. Line 2: 8-Character Netcode Status String

The second line is an exact 8-character status field generated by [`GameStateManager.debugStatusString`](../RadarMap/Managers/GameStateManager.swift).

### Character Positions & Definitions

| Index | Position | Indicator | Possible Values | Meaning |
|:-----:|:--------:|:---------:|:---------------:|:--------|
| **0** | **1st**  | **Server Upstream (Uplink)** | `U` / `0` | `U`: Upstream link to server attached and permitted to write.<br>`0`: Upstream link not attached or inactive. |
| **1** | **2nd**  | **Server Downlink (Listener)** | `D` / `0` | `D`: Realtime server listeners actively attached to room.<br>`0`: Realtime server listeners detached. |
| **2** | **3rd**  | **HS Stream Transmission Activity** | `P` / `W` / `0` | `P`: High-speed stream transmission active from iPhone.<br>`W`: High-speed stream transmission active from Apple Watch.<br>`0`: No high-speed stream data. |
| **3** | **4th**  | **LS Stream Transmission Activity** | `P` / `W` / `0` | `P`: Low-speed stream transmission active from iPhone.<br>`W`: Low-speed stream transmission active from Apple Watch.<br>`0`: No low-speed stream data. |
| **4..7** | **5th..8th** | **Reserved Placeholders** | `0000` | Reserved for future diagnostic channels; fixed to zeros. |

Total length is **always exactly 8 characters** (e.g., `UD000000`, `00W00000`, `000W0000`, `00WW0000`, `00000000`).

- **Typography**:
  - iOS: Monospaced 16pt bold, themed color with 0.6 opacity.
  - watchOS: Monospaced 11pt bold, themed color with 0.55 opacity.

## 4. Architectural Rules: Variable-Driven Evaluation

> [!IMPORTANT]
> **Strict Invariant: Zero Helper Functions**
> The debug display must never introduce helper methods, polling timers, event hooks, or side-effecting functions. It must be a **pure, read-only projection** evaluated synchronously from existing state variables.

### 1st Character: Server Upstream Link (`U` or `0`)
Driven by:
- `hasNetworkOwnership`: Whether this device is authorized to write to Firebase (watchOS always `true`; iOS only `true` when Watch lease is inactive/expired).
- `firebaseManager.isConnected`: Whether the Firebase client is connected.
- `firebaseManager.activeRoom != nil`: Whether a squad room session is active.

```swift
let isUpstreamAttached = hasNetworkOwnership && firebaseManager.isConnected && (firebaseManager.activeRoom != nil)
let upstreamChar: Character = isUpstreamAttached ? "U" : "0"
```

### 2nd Character: Server Listener Attached (`D` or `0`)
Driven by:
- `firebaseManager.attachedTelemetryRoomId`: Stored variable in [`FirebaseSyncManager.swift`](../RadarMap/Managers/FirebaseSyncManager.swift). Set to non-nil by `startTelemetryPolling(roomId:)` when listeners attach; cleared to `nil` by `stopTelemetryPolling()` when listeners detach.

```swift
let isListenerAttached = firebaseManager.attachedTelemetryRoomId != nil
let listenerChar: Character = isListenerAttached ? "D" : "0"
```

### 3rd Character: HS Stream Transmission Activity (`P`, `W`, or `0`)
Driven by existing high-speed lease variables in [`WatchConnectivityManager.swift`](../RadarMap/Managers/WatchConnectivityManager.swift) and [`GameStateManager.swift`](../RadarMap/Managers/GameStateManager.swift):
- `watchConnectivityManager.isWatchLeaseActive`: Published boolean tracking whether peer high-speed lease (`active_until`) is active.
- `watchConnectivityManager.latestRemoteActiveUntil`: Timestamp of remote peer's advertised lease.
- `watchConnectivityManager.localRole`: `.phone` or `.watch`.
- `isPhoneActive` / `isWatchActive`: Published activity state flags.

```swift
let isHSActive = watchConnectivityManager.isWatchLeaseActive || (watchConnectivityManager.latestRemoteActiveUntil > now)
let hsChar: Character
if watchConnectivityManager.localRole == .phone {
    hsChar = (isHSActive || isWatchActive) ? "W" : "0"
} else {
    hsChar = (isHSActive || isPhoneActive) ? "P" : "0"
}
```

### 4th Character: LS Stream Transmission Activity (`P`, `W`, or `0`)
Driven by existing low-speed reception variables in [`WatchConnectivityManager.swift`](../RadarMap/Managers/WatchConnectivityManager.swift) and [`GameStateManager.swift`](../RadarMap/Managers/GameStateManager.swift):
- `lastLowSpeedPayloadTimestamp` & `lastLowSpeedPayloadSource`: Receipt timestamp and source (`"W"` or `"P"`) of low-speed converged snapshots (active for 3.0 seconds).
- `watchConnectivityManager.localRole`: `.phone` or `.watch`.

```swift
let isRecentLowSpeed = (now - lastLowSpeedPayloadTimestamp) < 3.0
let lsChar: Character
if watchConnectivityManager.localRole == .phone {
    lsChar = (isRecentLowSpeed && lastLowSpeedPayloadSource == "W") ? "W" : "0"
} else {
    lsChar = (isRecentLowSpeed && lastLowSpeedPayloadSource == "P") ? "P" : "0"
}
```

## 5. Common Status String Patterns

| Status String | Device | Operational State |
|:-------------:|:------:|:------------------|
| `00000000` | Any | Idle / disconnected; no server session and no companion comms. |
| `UD000000` | iPhone / Watch | Standalone in active room: upstream attached (`U`), listeners attached (`D`), no companion comms. |
| `00W00000` | iPhone | Paired with Watch: Watch has active HS lease (`W`), iPhone yields uplink/listeners to Watch. |
| `000W0000` | iPhone | Paired with Watch: Watch sent low-speed update (`W`), HS idle. |
| `00WW0000` | iPhone | Paired with Watch: Watch has active HS stream and active LS stream. |
| `UDP00000` | Watch | Primary client in room: upstream attached (`U`), listeners attached (`D`), receiving HS stream from iPhone (`P`). |
| `UD0P0000` | Watch | Primary client in room: upstream attached (`U`), listeners attached (`D`), receiving LS stream from iPhone (`P`). |
| `UDPP0000` | Watch | Primary client in room: upstream attached (`U`), listeners attached (`D`), receiving both HS and LS streams from iPhone (`P`). |
